# OctoAcme Project Management Process Docs

Welcome to the OctoAcme Project Management documentation! This README provides an overview and central access point to the core processes that guide our project delivery.

## Project Management Overview

OctoAcme uses an **iterative, evidence-driven approach** to manage projects, featuring:
- **Clear ownership**: Each project has a named Project Manager and Product Lead
- **Frequent stakeholder engagement**: Regular syncs, demos, and transparent communication
- **Balance of planning with continuous improvement**: Detailed planning upfront, with built-in retrospectives and learning loops
- **Customer-first thinking**: Every decision prioritizes customer value and usability
- **Measured risk management**: Proactive identification and escalation of risks and dependencies
- **Transparent delivery workflows**: Clear workflows, acceptance criteria, and definition of done

Our approach ensures that projects stay aligned with business goals, teams have psychological safety to provide feedback, and improvements are captured and acted upon iteratively.

## Core Principles

1. **Customer-first**: Prioritize customer value and usability in all decisions
2. **Iterative delivery**: Deliver small, testable increments rather than big-bang releases
3. **Clear ownership**: Every project has named owners for accountability
4. **Data-informed decisions**: Measure impact and iterate based on evidence
5. **Psychological safety**: Encourage feedback, learning, and continuous improvement

## Key Artifacts

- **Project Charter / One-pager**: Problem statement, goals, success metrics, stakeholders
- **Roadmap and Release Plan**: Milestones, dependencies, and delivery timeline
- **Sprint/Iteration Backlog**: Prioritized work with acceptance criteria
- **Risk Register**: Tracked risks, impacts, and mitigation plans
- **Retrospective notes**: Learnings and action items for continuous improvement

## Project Lifecycle (High-Level)

1. **Initiation**: Define problem statement, identify stakeholders, create high-level timeline
2. **Planning**: Break down scope, estimate effort, identify dependencies and risks
3. **Execution**: Build, test, review, and iterate based on acceptance criteria
4. **Release**: Deploy to production, verify functionality, announce to stakeholders
5. **Close & Retrospective**: Capture learnings and plan improvements

## Communication Cadence

- **Daily standups**: 15-minute team check-ins on progress, blockers, and dependencies
- **Weekly PM sync**: Alignment between Project Manager and Product Lead
- **Twice-weekly team standups**: Delivery team syncs (or as agreed)
- **Monthly stakeholder updates**: High-level status and key metrics
- **Ad-hoc escalations**: As needed for blockers or business-impacting issues

## How to Use These Docs

1. **For new team members**: Start with the [Project Management Overview](octoacme-project-management-overview.md), then read the phase-specific guide for your current project stage.
2. **For project kickoff**: Use the [Project Initiation Guide](octoacme-project-initiation.md) to validate your idea and create the project one-pager.
3. **For planning**: Reference the [Project Planning](octoacme-project-planning.md) doc to create your backlog, milestones, and risk register.
4. **For day-to-day execution**: Follow the workflows and checklists in [Execution & Tracking](octoacme-execution-and-tracking.md).
5. **For release**: Use the [Release & Deployment](octoacme-release-and-deployment.md) checklist to prepare for and execute your release.
6. **For learning**: After each sprint or release, run a retrospective using [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md).
